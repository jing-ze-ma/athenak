conduction_transverse.cpp hand-rolled substage exchange (InitRecv/PackAndSendCC/spin RecvAndUnpackCC/ClearRecv/ClearSend, ~49 per stage, outside the task list): RecvAndUnpackCC launches the unpack kernel async; the next InitRecv re-posts MPI_Irecv into the same device recvbuf; a neighbour ahead lets the NIC overwrite it -> max|de| 1e8, |sum V de|/sum V|de| -> 1, dt collapse, Ftop 1.3e12 vs 4.2e13. Hidden with 2 blocks/rank (local copies stream-ordered) and in the task-list path (a stage of kernels between). Timing-dependent: detonated at different stages per binary (old prod a13cfd16 cycle 1 stage 4; pcrfix2 cycle 1 stage 3; 995ab40b cycle 0 stage 1 - the bvals window shortened the unpack kernel). X-tests: 2 ranks on 2 nodes fine; host-staged MPI (OMPI_MCA_accelerator=^rocm) removes the explosion but not all differences; HSA_XNACK irrelevant. FIX e9664224: Kokkos::fence() after each of the 3 unpacks (+ <hydro>/rad_tr_window switch, default true). F4 (4 ranks x 2 nodes, GPU-aware) bitwise = 2-rank reference in time/dt/E/Ftop (momenta/KE 1e-16 reduction order); 259 ms/cycle vs 376 broken / 380 at 2 ranks -> real strong scaling now. Residual 1e-4 in max|dT*|/T* between rank counts is a per-rank diagnostic. prod_taper (2 ranks, 1 node) was unaffected; the held 4-node chain would have been the first hit. ALSO applies to any multi-node run of rg/dhj IF they use rad_implicit_ang (they refuse it on curvilinear meshes, so no). See [[bstar-prod-cost-profile]], [[bstar-regate-2026-09-16]].

PRODUCTION-LAYOUT SMOKE 09-15 (m3pcr/prof/p_prod8gpu vs p_prodfull2gpu, full 336x216x216 mesh, binary e9664224): 8 ranks x 4 nodes bitwise with 2 ranks x 1 node in time/dt/Ftop/user.hst, tot-E 1.3e-16; 247 ms/cycle (2-rank full mesh 644) -> 40 turnovers = 18.4 h on 8 GPUs, one 23:55 link. max|dT*|/T* differs 9e-5 between rank counts (diagnostic only).
