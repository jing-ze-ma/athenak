## Traps learned

- `Driver::Finalize` writes EVERY output at tlim regardless of dt/last_time -- a bin dump
  cannot be fully suppressed.
- A command-line `block/par=value` override needs the key to be **present in the athinput**
  already (e.g. `mesh/polar_x3_shift=`); otherwise it is silently ignored.
- The cyclediag `rt_de` is the **LAST RK stage only** (the applied energy change), not the
  cycle total.
- `rt_T` is the **EOS T of (rho,e) at the START of the last stage**, so it can exceed
  T(w_eint at the end of the cycle) by a lot when RT removes half the energy in that stage.
- **The collapse image moves between vertex copies between runs** -- pin `diag_gid` to the
  block that actually aborts in THAT binary, not the one from the previous run.
- A run shorter than an output dt writes **no hst and no event log** (the twin's event log
  never fired: log dt 3.05e4 > the run length). Set `output1/dt` and `output2/dt` small in any
  short diagnostic run.
- `rad_tmax_kappa` below ~6e3 K can **RAISE** kappa, because kappa_R(T) falls faster than T^3
  in the 5-6.5e3 K table region. Cap only at >= 3e4 K, where the table is clamped.
