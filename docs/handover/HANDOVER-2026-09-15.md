## 1. What changed today (one paragraph)

Four bugs were found and fixed, and both stellar-box productions were launched on the fixed binary.
The exact implicit column solve (`rt_implicit_column = 3`, "mode 3") was **never given the imposed bottom
flux** — on both its solver paths — which is what the He column's "flux collapse" was and what the
long-standing "0.707 flux loss in every ramp config" signature was; fixed on both branches and re-gated
(B star `Ftop/Fb = 1.00000`, He `Ftop/Fbot 0.996-0.998`), which invalidates every pre-09-15 mode-3 He
conclusion and forced the whole He qualification matrix to be regenerated.  Chasing the B-star chain's
4-node scaling then exposed a **pre-existing GPU-aware-MPI race in the hand-rolled RKL1 transverse halo
exchange** that silently produced a wrong angular source (Ftop 30x low) at one MeshBlock per rank across
nodes on *every* binary built to date — the held 4-node chain would have been the first production to run
through it; a `Kokkos::fence()` after each unpack cures it and 4 ranks x 2 nodes is now bitwise with 2
ranks, which also restored real strong scaling (376 -> 259 ms/cycle).  Box **restarts were not bitwise**
(the dynamic WB background cache was rebuilt from a different phase after a restart, and the first dt was
recomputed): fixed to roundoff, with the remaining 1-ULP residual traced to the non-idempotent tabulated
EOS inversion and deferred.  On the performance side PCR (2.07-2.4x the Thomas column on the gate box),
the bvals x1 window (1.12x at production occupancy) and `rad_tr_halo_every=2` (-51 % on the transverse
operator) were measured and gated bitwise, while Newton tol 1e-6, one column solve per cycle, decomposition
reshaping and more GPUs before the fence were all rejected.  The B-star `prod_m3` chain and the He `box_m3`
chain are running; an audit cleared the red giant and dhj of the day's bug classes except for one latent
dhj double-count, which is now a fatal.

## 2. Bugs found and fixed

### 2.1 Mode 3 never received the imposed bottom flux (both the Thomas and the PCR path)

**Symptom.**  `bench/hestar_fecz/qual_m3`, 1-D He column, 300 time units per arm.  Mode 0: `Ftop/Fcut`
0.956, `E` 0.996.  Mode 3: Q1 `Ftop/Fcut` **0.030**, `E` 0.363; Q3 (cfl 0.15) 0.081 / 0.449; Q4 (cfl 0.45)
0.009 / 0.323.  The collapse is monotone from t=0 (Q1 ratio 0.88, 0.73, 0.55 at t = 0.55, 1.0, 1.5) and
scales with dt, i.e. an O(dt) drain in the apply, not a steady-state error.  Q1b (`rad_x1_uform=false`,
`kiter 1`) was **bitwise identical** to Q1 — those switches do nothing under mode 3, so the control arm
that had been running tested nothing.  Newton was healthy throughout (it_max 3, residual 1e-12).

**The budget that localised it.**  From the hst (`F_bot = rad_flux_inner = 2.475e15`, area 7.03e12):
`dE/dt = -A*Ftop` **exactly**, and the residual against `A(F_bot - F_top)` is `-1.0 F_bot*A` at t = 5, 20,
100 — the injected bottom flux is never deposited in the gas.  `Fcut/F_bot` is pinned at 1.0000 to 8 digits
because it is the imposed value, not a measurement; `Ftop/F_bot` = 0.73, 0.12, 0.05, 0.03 at t = 1, 5, 20,
100.  (Note for anyone reading these files: `user.hst` has **no** `Fbot` column — columns 4/7 are the
squares of 3/6.)

**Cause.**  `RTCol3::Solve` formed `dbdtau` from `Bb(ic) - Bb(ic+1)` alone —
`src/utils/two_stream_column_implicit.hpp:512`.  The explicit sweep has an override,
`if (bot_flux > 0) dbdtau = 3*bot_flux/(4*pi)` at `src/utils/two_stream_rt.hpp:2082`, and mode 3 had no
counterpart.  The same omission was then found on the **PCR** path,
`src/utils/two_stream_column_partition.hpp:115-120`, which forms `dbdtau` the same way.

**Fix.**  `rg-box-convection` **1c45e532** ("rt_implicit_column 3: pass rt_bottom_flux to the column
solve") — a `RTCol3::bot_flux` member set in the mode-3 setup and applied after the `dbdtau` block;
`rg-box-pcr` **1fdce2b0** ("... (Thomas and PCR)") carries the same fix plus the partition path
(`if (c.bot_flux > 0.0) dbdtau = 3.0*c.bot_flux/(4.0*M_PI);` after line 119).

**Gate evidence.**
- He, `bench/hestar_fecz/qual_m3`: Q1f (fix, Thomas, `wt_rgbox/build_hip_botfix`, md5 `03dba9f0`)
  `Ftop/Fbot` 0.943, 0.996, 0.996, **0.998** at t = 1, 5, 20, 300; `E/E0` 1.021; 3289 cycles vs 7613
  (dt is no longer shrunk by the spurious cooling).
- B star, `bench/bstar_fecz/final_gate`: G3f (fix, Thomas) `Ftop/Fb` **1.00000**, clean; G3p (fix + PCR
  nseg 32, `wt_m3acc/build_hip_pcrfix`, md5 `c9a196b6`) `Ftop/Fb` 1.00000.  Cost-neutral: zone-cycles/s
  G3 1.04e5 = G3f 1.06e5.
- Mode 0 is untouched: G0f and G0p are **bitwise** = G0ref (`bitwise.py`).
- **The B star passed before the fix only by physics coincidence** (its bottom cells are radiative, so the
  local Planck gradient happened to carry the right flux); the He column, being much thicker and
  kappa-unstable, did not.  G3p also "passed" with the unfixed PCR path for the same reason, while He Q1p
  collapsed bitwise like the unfixed run — hence the re-gate G3p2 / Q1p2.
- G3p2 PASSED and tracks G3f: v_rms 894 vs 882, `Ftop` 1.00000, **2.59e5 zone-cycles/s = 2.4x Thomas**.

**Consequence.**  Every pre-09-15 mode-3 **He** conclusion ran without the bottom flux and had to be
discarded: the flux-collapse arms, the ramp convergence matrix, and the "0.707 flux loss in every ramp
config" signature (which was this bug).  The mode-0 organ-pipe diagnosis stands.  The matrix was
regenerated (§5).

### 2.2 The RKL1 transverse halo races with GPU-aware MPI across nodes (pre-existing, timing-dependent)

**Symptom.**  Strong scaling of the production mesh went the wrong way: same 4-block mesh, binary
`995ab40b`, 2 ranks x 2 blocks **380-390 ms/cycle**, 4 ranks x 1 block on 2 nodes **376 ms/cycle**
(efficiency 0.52, no speedup).  Worse, the 4-rank run **diverged from the 2-rank run inside cycle 0**
(stage-2 `rad_implicit_ang` needed 3012 planes vs 2942; cycle 1 max z_i 4225 vs 3015), i.e. the answer
depended on block-to-rank placement.  With the transverse operator off (`rad_implicit_ang=false`,
`rad_sts_perplane=false`, `rad_cap_ang=0`, `rad_tr_tau_lo/hi 1e30/1e31`) scaling was healthy — noang2
311 ms/cycle, noang4 186, efficiency 0.83, and the two rank counts agreed to roundoff.  With the operator
on, the 4-rank run was simply **wrong**: `Ftop` 1.33e12 vs 4.21e13 (30x low).

**Bisect: pre-existing.**  The old production binary (Thomas, no PCR, no window, md5 `a13cfd16`) blows the
implicit angular source on 4 ranks x 2 nodes too (max|de| 2e8, `|sum V de| / sum V|de| -> 1`) at cycle 1
stage 4; `pcrfix2` at cycle 1 stage 3; `995ab40b` at cycle 0 stage 1 — different stages per binary, i.e.
**timing-dependent**, and inter-node only (1 rank x 4 blocks == 2 ranks x 2 blocks == 2 ranks on one node,
all bitwise).  `prod_taper` (the finished 20-turnover production) ran 2 ranks on **one node** and is
therefore unaffected; the held 4-node chain would have been the first run through the broken path.
(`max|dT*|/T*` is a per-rank diagnostic and is rank-count dependent even for bit-identical states — do not
read it as a discrepancy.)

**X-tests that cornered it.**  X1 (2 ranks on 2 nodes, GPU-aware MPI) = bitwise correct, so it is not
inter-node transport as such.  X3 (4 ranks x 2 nodes, host-staged MPI: `OMPI_MCA_accelerator=^rocm`,
`UCX_MEMTYPE_CACHE=n`) removed the cycle-0 explosion (first 3 lines = reference) but not all differences
(t(60) 82.0 vs ref 89.8).  X4 (`HSA_XNACK=0`) irrelevant.  E2 (new switch `<hydro>/rad_tr_window`, binary
`build_hip_trwin` md5 `1327a8a9`) showed the windowed exchange was broken inter-node despite the symmetric
range argument, with a second defect behind it.

**Cause.**  The hand-rolled substage exchange in `src/diffusion/conduction_transverse.cpp:470-476`
(`InitRecv` / `PackAndSendCC` / spin on `RecvAndUnpackCC` / `ClearRecv` / `ClearSend`, ~49 rounds per stage,
outside the task list): `RecvAndUnpackCC` launches the unpack kernel **asynchronously**, and the next
`InitRecv` re-posts `MPI_Irecv` into the **same device receive buffer**; a neighbour that is ahead lets the
NIC overwrite the buffer while the unpack kernel is still reading it.  Hidden with 2 blocks/rank (the local
copies are stream-ordered) and hidden in the task-list path (a whole stage of kernels sits between the
rounds).  The MPI drain itself is correct on paper, and the hydro halo over the same code is fine.

**Fix.**  `rg-box-pcr` **e9664224** ("conduction_transverse: fence after every halo unpack;
rad_tr_window switch"): a `Kokkos::fence()` after each of the 3 unpacks, plus the `<hydro>/rad_tr_window`
switch (default true).

**Gate evidence.**  F4 (4 ranks x 2 nodes, GPU-aware) is **bitwise** = the 2-rank reference in
time/dt/E/Ftop (momenta/KE differ at 1e-16 by reduction order), at **259 ms/cycle** vs 376 broken / 380 at
2 ranks — real strong scaling for the first time.  Production-layout smoke `m3pcr/prof/p_prod8gpu` vs
`p_prodfull2gpu` (full 336x216x216 mesh, binary e9664224): 8 ranks x 4 nodes **bitwise** with 2 ranks x 1
node in time/dt/Ftop/`user.hst`, tot-E 1.3e-16, **247 ms/cycle** (2-rank full mesh 644) -> 40 turnovers in
**18.4 h on 8 GPUs, one 23:55 link**.  On He the same binary gives H8 (8 ranks x 4 nodes) bitwise = H2.
G3g PASSED (bitwise = G3e).

**Scope.**  This also applies to any multi-node run of the red giant or dhj **if** they used
`rad_implicit_ang` — they refuse it on curvilinear meshes (`conduction.cpp:227`), so they are not affected.

### 2.3 Restarts were not bitwise: the WB background-cache phase, and the recomputed dt

**Symptom.**  The restart gate on the B-star production candidate (`final_gate/R_straight` vs `R_cont`):
the first post-restart cycle differs by **KE 5.3e-4 relative**, E 1.9e-11, dt 2.5e-10, time 2.8e-13, then
diverges chaotically.

**Cause (two).**  (1) `src/hydro/hydro_fluxes.cpp:167-176` rebuilds the dynamic WB background `wbq0` at
stage 1 whenever `ncycle % wb_cache_every == 0` or `!wb_cache_built`, and `wbq0` is **not in the restart
file** (`restart.cpp` writes `u0`, `b0`, `wtemp`, time/dt/ncycle).  A restart at a non-multiple of
`wb_cache_every` (10) therefore rebuilds the background from a **newer** state than the straight run is
carrying, up to 9 cycles apart — a momentum imbalance, visible in KE first.  (5c0b98e4 had fixed only the
zero-background half of this; this is the "mom1 1e-7 residual" left open with 929d752d.)  (2) `driver.cpp`
wrote the restart file **before** `Mesh::NewTimeStep`, and `Driver::Initialize` recomputed dt from the
post-split state, while the running code used the in-stage dt.

**Fix.**  `rg-box-pcr` **7ca9c57f** ("restart: rebuild the WB cache from the saved state, and restore the
saved dt"): at the end of `Restart::WriteOutputFile`, set `wb_cache_built = false` for hydro and mhd so
both the running process and the restarted one rebuild from the same state; in `driver.cpp` move the rst
outputs after `Mesh::NewTimeStep` via an `out_is_due` lambda; `Initialize` keeps the restored dt when
`res_flag`.  Everything else (mode-3 workspace, ALI, RKL1 counts, potential, BCs) was already restart-clean.

**Gate evidence.**  `Rx_straight` / `Rx_cont` (binary `athena_pinned_rstfix`, md5 `8b1bcb99`): time
3.6e-15, dt 1.1e-13 (1 ULP at the first row), tot-E 1.1e-14, KE **3.1e-10** max over 400 rows — from
8e-2 before.  The straight run is unchanged before the first rst write and changes after it (the cache
invalidation, as designed).  G3e (7ca9c57f, md5 `924480c8`): bitwise = G3d until the first rst write at
t = 1000, then departs by that invalidation; v_rms 861, M_max 0.236, `Ftop` 1.00000, 2.59e5 zone-cycles/s.
Bisect: the old production binary `a13cfd16` had the identical defect (KE 5.28e-4), and fix+Thomas ==
new+Thomas bitwise, so PCR and the bottom-flux fix are exonerated.

**Deferred: the 1-ULP residual.**  The rst now stores and restores the next dt bitwise; the residual comes
from `driver.cpp:851` `InitBoundaryValuesAndPrimitives` running `ConToPrim` on the restart path, and the
tabulated-EOS inversion is **not idempotent** — `eos.hpp:428` warm-starts with `zg = log10(tguess*temp_cgs)`,
round-tripping `wtemp` through `Pow10`/`log10` (1 ULP off), and `SolveLog` (`eos_table.hpp:350-380`) always
takes one update.  `w0`/`wder` end up 2e-15 off and dt 5e-16.  The exact fix is to store `w0`/`wder` in the
restart and skip that `ConToPrim` (a format change), or to cache `ltk` instead of T with an early return in
`SolveLog`.  **Deferred**: restarts are exact to roundoff now and this is not worth a format change for
production.

### 2.4 dhj could inject the internal flux twice (latent; now a fatal)

**Symptom.**  None observed — latent, found by the audit in §2.5.  `src/pgen/deep_hot_jupiter_rt.cpp:442`

already does.  Still to do: delete the dead legacy solvers with hard-coded `Tint` 100/500 at
`deep_hot_jupiter_rt.cpp:2711, 2936` (never called).

### 3.4 Decomposition shape: a dead lever

S22 (2x2 blocks, 8 horizontal neighbours) vs S14 (1x4 slabs, 2 neighbours), 4 ranks x 2 nodes, full
336x216x216 mesh, 60 cycles: **403 vs 408 ms/cycle**, and bitwise identical physics.  The per-swap cost is

are dead levers; only **fewer swaps** help (and, for He, fewer substages).  Per cell: 1.03e-7 ms/cell at 2
blocks/rank vs 1.32e-7 at 1 block/rank (F4).

### 3.5 `rad_tr_halo_every`: N = 2, -51 % on the operator, bitwise

Commit **76b42ca8** ("conduction_transverse: exchange the RKL1 halo every N substages; faces-only option",
`<hydro>/rad_tr_halo_every`, default 1).  Method: refill all `nghost` layers once per N substages and
advance the recurrence on a **shrinking ghost skin** (`Y_{j-1}` via the 5-point cross, `Y_{j-2}`
pointwise; N >= 3 also exchanges `Y_{j-2}`); the ghost coefficients are built `nghost` deep when N > 1.

| arm (4 ranks x 2 nodes) | ms/cycle |
| --- | --- |
| F4 (every = 1) | 259.3 |
| faces_only | 236.0 |
| every = 3 | 227.7 |
| **every = 2** | **221.8 (best)** |
| floor without the operator | 186.5 |

Gate arms `m3pcr/prof/C4a-d`, `C2c` against F4/F2: **all bitwise** (hst, `rad_implicit_ang` lines,
time/dt), at both 2 and 4 ranks.  `faces_only` (`skip_x2x3_diag` in `MeshBoundaryValues`, 9 symmetric
sites) is refused with N > 1 (the skin reads the diagonal ghosts), and `rad_sts_split` + N > 1 is fatal.
Binary `build_hip_prod76b42ca8` (md5 `afa1d71f`).  **Usage: put `rad_tr_halo_every = 2` in the `<hydro>`

input embedded in the rst, so the key must already be there); the restart format is unchanged and the
change is bitwise-equivalent.  The He box runs on it since 09-15 ~03:15 (§5.2).

- **`cvfreeze 2`**: no gain.
- **Host-staged MPI** (`OMPI_MCA_accelerator=^rocm`): was a zero-cost stopgap (378 ms/cycle) for §2.2,

### 5.4 The He lid mode: a damped box acoustic fundamental, 151 s

Characterised from `relax1d_m3`'s `user.hst` at 5 s cadence: a **global standing acoustic mode of the whole
1-D box**, fundamental **151 s** = 2x the box sound crossing time (75.7 s), overtone 76 s, one velocity node
at i = 81, amplitude ~rho^-1/2 so it peaks at i 124-128 (rho 1.5e-8..7.6e-9, just below `eos_rad_rho_lo`).
It is **decaying**, e-fold 2800 s, to a `Ttop` floor of 3e-4 rms (p2p 1.4e-3) with `Ftop` p2p 1.9e-3;
`velx` is 3-4 % of c_s in the lid.  It is not thermal (the lid's t_cool is 1e-4 s) and not an artefact —
but the 150 s dump cadence **aliases** it, and the previously reported "top 14 cells oscillate 27 % between
dumps" was that aliasing of a ~3e-2 rms mode at i = 126.  The "14 cells" are i 115-128; the top 5 are
frozen.  Implication for the 3-D box: it is the same organ-pipe class as the shallow-ramp instability, here
damped — **watch `Ttop` in the 3-D hst**.
