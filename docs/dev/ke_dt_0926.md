# ke-dt-0926: why the 3-D M1 He box KE depends on dt, and the coupling_split prototype

Run tree (viper): `/viper/ptmp2/jinma/kedt_0926` (RESUME.md holds every job id and number).
Start state: `bench/m1_vet3dcfl_0923/C15/rst/m1slab.00008.rst` (t = 3800 s), input
`hebox_cfl_0926/inp/box.athinput` (vet_sc, mg_gf, hesdirk2, vimp). Growth rates are the slope of
ln KE_h (100-s running mean) over t = 4000-5000 s (`scripts/rate.py`).

## 1. Diagnosis (binary 7d68dd70)

- Mode: horizontal |k| = 7-8 (lambda 1.4e8 cm), period ~118 s, v1 peaked mid-box; plus a radial
  acoustic family (111 / 59 / 30 s). Not convection (F_conv/F < 1e-4); laminar (noise twins 1e-8).
- gamma(KE_h) of hesdirk2: 3.66 / 5.28 / 8.85 / 12.8 e-4 /s at cfl 0.15 / 0.3 / 0.6 / 0.9
  (dt 0.081 / 0.161 / 0.317 / 0.468): linear in dt.
- Ablations at cfl 0.3 / 0.9:
  - dbg_gas_force = false: -2.4e-5 / -3.3e-5, the mode decays at any dt. So the radiative force
    drives it.
  - dbg_gas_heat = false: explodes, so the exchange damps it.
  - These change nothing:
    - implicit_vimp off;
    - one_pass off, predictor order 1, implicit_tol 1e-10 (identical to 3 digits);
    - implicit_closure_lag = pass (identical);
    - closure = eddington (5.0e-4 / 1.27e-3);
    - time2_vet_extrap (identical).
  - implicit_opac_update: slightly more growth. Transverse force off: same slope.
- The error follows the radiation coupling interval, not the hydro dt. implicit_mr_every = 2 at
  cfl 0.3 equals implicit_mr_every = 4 at cfl 0.15 (-1.71e-4); the sign depends on the scheme:

| scheme | slope (per s of coupling interval) | gamma extrapolated to 0 |
|---|---|---|
| hesdirk2 (default) | +2.0e-3 | 2.0-2.2e-4 |
| be | +5.5e-3 | 1.6-1.8e-4 |
| Strang multi-rate SDIRK2 | about -1.0e-3 | 1.5-1.8e-4 |

  **gamma0 = 1.5-2.2e-4 /s is the dt-converged growth rate** (at this resolution).
- A reversible toy split (Heun gas pressure plus a radiation-pressure kick, `ana/toy.py`) gives
  only O(w^4 dt^3) errors. The first-order term needs the stiff exchange: t_ex << dt, and diffusion
  across the mode is faster than dt. This is order reduction of the coupling in the stiff limit.
  The WB gravity cache is rebuilt every stage (wb_cache_every = 0), and arad_ref is a fixed
  profile. So the stale-reference bug of the 09-15 f-mode is not present here.
- The temporal self-convergence (cfl 0.8 / 0.4 / 0.2 / 0.1 over 100 s, `scripts/order.py`) shows
  the same thing. For hesdirk2, rho and E are 2nd order, v1 is 1.7-1.8, and v_h is 1.0.

## 2. Prototype `<rad_m1>/coupling_split` (commit a6c94c66 + style)

Read only when named; default = off, bitwise. Values:
- `strang`: the Heun hydro alone, then R(dt) by the multi-rate SDIRK2 (MRSolve, k = 1) every step.
  This is Strang up to a non-accumulating offset.
- `alternate`: H R on even steps, R H on odd steps.
- `mix`: `coupling_mix_h2` hesdirk2 steps, then `coupling_mix_s` strang steps (default 1:2).

It needs hesdirk2 and implicit_mr_every = 1. The step counter travels in the multi-rate restart
header (mr_cnt).

Results (gamma KE_h, 1/s; runs2/, runs_ord/):

| arm | cfl 0.15 | 0.3 | 0.6 | 0.9 |
|---|---|---|---|---|
| default hesdirk2 | 3.66e-4 | 5.28e-4 | 8.85e-4 | 1.28e-3 |
| strang | 1.01e-4 | -4.3e-6 | -1.71e-4 | blows up in 20 s |
| alternate | | -4.35e-4 | -8.29e-4 | blows up |
| mix 1:2 | 1.93e-4 | 1.75e-4 | 1.71e-4 | blows up |
| mix 1:1 | | 2.63e-4 | | 4.28e-4 |

- Gate (a): `mix 1:2` is flat and inside gamma0 for cfl 0.15-0.6. strang and alternate fail
  (strang reproduces the multi-rate slope, as its coupling interval predicts).
- Gate (b), order: mix v_h 1.49 / 1.10 (0.8 to 0.4 / 0.4 to 0.2); strang v_h 1.06. **No splitting
  is 2nd order in v_h.** The mix cancels the growth-rate error on average only; the per-step
  error does not cancel. FAIL.
- Gate (c): every split variant blows up at cfl 0.9 (a radial burst within 20-60 s). Cost at
  cfl 0.3 (1 GPU, wall per simulated s): default 0.240, strang 0.289, mix 0.369 (38.7 / 46.6 /
  59.5 ms per cycle). FAIL at 0.9.
- Gate (d): keys off are bitwise vs dc5faabc on box, T-S4 wedge, sph_wedge and dhj. Restarts are
  bitwise with base, k1 and the key on (box strang / alternate / mix, sph_wedge strang). The
  sph_wedge runs with strang. PASS.
- Lid check (user hst 4000-5000): F1top/F = 1.000002 in every arm; std 3e-6 (default) vs 5e-6 to
  1.3e-5 (splits). The lid is not broken.

## 3. Verdict on coupling_split (superseded by section 5)

- `mix 1:2` gives the dt-converged growth rate (1.7-1.9e-4) at cfl <= 0.6. It is an empirically
  tuned cancellation of two first-order errors, not a 2nd-order scheme; its ratio is problem
  dependent, and it is unstable at cfl 0.9.
- Use it only as a diagnostic. Do not use it for production and do not make it the default.
- The dt-converged KE is bracketed by hesdirk2 (above) and Strang multi-rate (below) at the same
  cfl. `scripts/kesat.py` reads the long MR runs (job 11990312).
- A real fix needs a coupling that stays asymptotically 2nd order in the stiff exchange limit.
  That means the gas internal-energy and pressure response to compression must be inside the
  implicit stage, i.e. the p dV work, or the gas pressure, treated implicitly with the exchange.
  This is future work.

## 4. Locating the first-order term (09-27)

Order test = 100 s from C15 rst 8, cfl 0.8/0.4/0.2/0.1 (`scripts/job_ord*.sh`, `scripts/order.py`).
Relative L1 error of v_h, 0.4 -> 0.2, and its order:

| arm | v_h error | order | note |
|---|---|---|---|
| hesdirk2 default | 2.17e-2 | 1.02 | rho, E 2nd order |
| time2_tableau = trbdf2 | 2.20e-2 | 1.01 | ESDIRK with stage order 2 |
| + implicit_opac_update, converged | 2.0e-2 | 1.01 | rho/E errors 8x smaller |
| time2_vstage | bitwise = default | | beta ~ 1e-6 |
| implicit_eos_cache = false | bitwise = default | | |

- The TR-BDF2 tableau (`time2_tableau = trbdf2`, commit 2312fbaf) makes no difference.
- implicit_mr_nsub, the radiation step R(Delta) taken as n substeps: more substeps give MORE
  damping (-1.7e-4, -4.3e-4, -8.3e-4 /s). So the multi-rate path carries two opposite errors: the
  H-R split (damping) and R's own (anti-damping).
- R alone (`dbg_hydro_off`, commit b57b6a91, hydro stages skipped), order in the substep:
  - SDIRK2 R: v and E 1st order;
  - TR-BDF2 R (`implicit_mr_tab`): identical;
  - converged opacity update, or Eddington, alone: still 1st order;
  - Eddington + converged opacity: the v error drops 5 orders (8e-8, noise).
  So inside R the 1st-order v comes from the vet_sc tensor and the opacities frozen at the
  stage start. E stays 1st order (1e-5) in every R arm.
- In the coupled box, those two lags are not the growth driver: Eddington + converged opacity
  gives the same gamma slope.
- A linear stiff toy of the IMEX structure (`ana/toy2.py`) is 2nd order for both tableaus.

## 5. The cause: the energy bookkeeping of the WB reference force

- With `problem/wb_phi_eff = false` and `force_reference = none`, gamma(KE_h) is 2.04e-4 at
  cfl 0.3 and 2.25e-4 at cfl 0.9, i.e. dt-independent. That arm is not well balanced: KE1
  jumps to 8e28 as a steady upward flow.
- Under `wb_arad` (rad_m1_coupling.cpp header):
  - the solve hands the gas the work of the FULL radiative force, and the radiation pays it;
  - the WB gravity source (box_convection BoxConvSrcs) applies rho arad_ref with NO energy
    term;
  - the internal energy is balanced only "to O(dt^2), the two vbar are a stage apart". That is
    an O(dt^2) error per step, 1st order globally, on a force of 0.75 g.
  - The stage-consistent work in the E row (time2_vstage) was also refused whenever fref was
    set.
- Fix `<rad_m1>/force_reference_work = split` (commits f66ea71b, d5f95e1c; read only when
  named, default `full` = bitwise):
  - the WB source gives the gas the work of its rho arad_ref kick at its own stage (trapezoid
    velocity of the kick);
  - the solve gives the gas only the residual's work (the exact kinetic-energy change of the
    residual kick);
  - the radiation pays both, in the E row of the stage solve (the wimp path, allowed with
    fref under split).

Gate (a), gamma(KE_h) over 4000-5000 s (runs8/WR_c*):

| cfl | 0.075 | 0.15 | 0.3 | 0.6 | 0.9 |
|---|---|---|---|---|---|
| split | 2.19e-4 | 2.22e-4 | 2.29e-4 | 2.45e-4 | 2.59e-4 |
| default | | 3.66e-4 | 5.28e-4 | 8.85e-4 | 1.28e-3 |

- Residual slope about 8.7e-5 per s of dt (27x smaller). The dt->0 limit is 2.16e-4.

Gate (c), lid: F1top/F = 0.99997-0.99999 (default 1.000002), std unchanged, V1max unchanged,
mass exact, total-energy drift -9.6e-6 (= default).

Gate (b), order 0.4 -> 0.2, split:
- rho 1.95, E 1.82, v1 1.85; v_h 0.88 (error 8.8e-3, 2.5x smaller than default).
- The growth part of the v_h error drops 10x (1.6e-3). The rest is phase error, largest in
  the thin top (i >= 72).
- split + Eddington: v_h 1.13-1.37.
- The implicit_opac_update path makes rho and E 1st order. That error sits in the top layers
  (i >= 70), is uniform across the plane, and is about 5e-5 relative in rho. It needs repair
  before the opacity lag can be removed.

## 6. Status at 09-27 morning (superseded by section 7)

- `force_reference_work = split` gives the right, nearly dt-independent growth rate. It is the
  candidate fix for the KE dt dependence.
- Remaining for full 2nd order in v:
  - the vet_sc tensor and the opacities are frozen at the stage start
    (time2_vet_extrap does not help);
  - the implicit_opac_update path has its own 1st-order top-layer error.
- Diagnostic keys on the branch (default off, read only when named): implicit_mr_nsub,
  dbg_hydro_off, implicit_mr_tab; time2_tableau; coupling_split.

## 7. The cure: split + converged opacity update (09-27)

Setting: `force_reference_work = split`, `implicit_opac_update = true`,
`implicit_one_pass = 0`, `implicit_tol = 1.0e-8`.

- Commit c0389721 puts the split in separate kernels, so the default write-back and the WB
  source are untouched (bitwise; the version in a single kernel was not).
- The gas's reference work uses the stage-start velocity. The earlier trapezoid term was a
  dt^2 energy sink per stage and caused the "opac_update is 1st order" artefact.
- Commit 81e88e44: sph_wedge gives the reference work too, and rad_m1 fatals on split unless
  the pgen sets `fref_wsplit_ok`.

Gate (a), gamma(KE_h) over 4000-5000 s (runs10, tol 1e-12): 2.15e-4 at cfl 0.075, 0.15, 0.3,
0.6 and 0.9, identical to 3 digits. That is gamma0.

Gate (b), order 0.8->0.4 / 0.4->0.2, runs_ord/W10O8:

| variable | order | error at 0.4->0.2 | default error |
|---|---|---|---|
| v1 | 1.94 / 1.96 | 1.65e-4 | 2.3e-2 |
| v_h | 1.95 / 1.80 | 2.58e-4 | 2.2e-2 |
| rho | 1.94 / 1.87 | 3.8e-7 | 4.7e-5 |
| E | 1.69 / 2.08 | 1.9e-7 | 1.7e-5 |

- tol 1e-10 and 1e-12 give the same errors.
- tol 1e-6 loses convergence at small dt, and implicit_maxit = 2 is unstable. So tol 1e-8 is
  the setting.

Cost (runs_time2, interleaved on apudev, same binary k11, 1 GPU each, 150 s from t = 3800):

| setting | cfl | wall per sim s | ms / cycle | Picard / solve |
|---|---|---|---|---|
| default | 0.3 | 0.299 | 48 | 1.13 |
| default | 0.9 | 0.170 | 82 | 1.58 |
| split + opac 1e-8 | 0.3 | 0.600 | 97 | 4.8 |
| split + opac 1e-8 | 0.9 | 0.256 | 125 | 5.4 |

- Split alone costs the same as the default (48.8 vs 48.4 ms per cycle, runs_time).
- Equal accuracy (v_h self-convergence error):
  - the default at cfl 0.3 has about 1.6e-2, and a growth rate 2.5x too large;
  - split + opac at cfl 0.9 has about 1.3e-3 (2nd-order extrapolation of 2.6e-4 at cfl 0.4)
    and the exact growth rate, at 0.86x the default's cfl-0.3 cost;
  - the default would need cfl of about 0.024 (about 3.7 wall s per sim s) for the same v_h
    error, i.e. about 15x more.

Simple tests with the keys ON:
- Lowrie-Edwards M2, N512, CPU (le/): the h2 and keys-on error tables are identical to all
  digits printed at every cfl (0.4 to 0.05). rho 2.19e-5 to 3.04e-7, T 1.58e-5 to 2.17e-7,
  E 7.5e-5 to 8.1e-6; the h2val README values are reproduced. This problem has no force

- Radiation-acoustic wave (P100, tau 10, N64, radwave/): keys on = default to all digits;

- sph_wedge: see RESUME.md (job 11995660).

### Recommendation

For M1 runs with `force_reference = wb_arad` (He box, sph_wedge):
- use `force_reference_work = split` + `implicit_opac_update = true` +
  `implicit_one_pass = 0` + `implicit_tol = 1.0e-8`, which may run at cfl 0.9;
- the default (full work) gives a growth rate that is wrong by (2.0e-3 per s) x dt at the
  default hesdirk2 tableau.

## 8. Default flip for force_reference = wb_arad (branch m1-keydefault-0927, 09-27)

User decision 09-27: the section 7 key set becomes the default for M1 runs with
`force_reference = wb_arad`. Which keys act where:

| key | acts | new default with wb_arad | without wb_arad |
| --- | --- | --- | --- |
| `force_reference_work` | wb_arad only (read only when named otherwise) | `auto` = split when the pgen gives the gas the reference work (box_convection, sph_wedge: `fref_wsplit_ok`), else full (e.g. rad_m1_tests2 sph_atm); resolved and echoed in `SetForceReference` | unchanged (no effect) |
| `implicit_opac_update` | any implicit M1 with T-dependent opacity (general) | true | false (unchanged) |
| `implicit_one_pass` | any implicit M1 (general) | 0 | 8 when the fast-kernel/predictor defaults are on, else 0 (unchanged) |
| `implicit_tol` | general | 1e-8 (was already the default) | 1e-8 (unchanged) |

`implicit_opac_update` and `implicit_one_pass` are general keys and are not no-ops without
wb_arad, so their defaults change only when `force_reference = wb_arad`.
The explicit values keep the old scheme: `force_reference_work = full`,
`implicit_opac_update = false`, `implicit_one_pass = 8`. All three are recorded with GetOrAdd.

**Old inputs and restarts change behaviour.** An input or restart file with
`force_reference = wb_arad` that does not name these keys now runs split + opacity update
+ no one-pass acceptance. The pgens now set `fref_wsplit_ok` *before* `SetForceReference`.
Restart files written by the merge commit 86d7c115 or earlier record `implicit_opac_update`
and `implicit_one_pass` whenever they were read, so they keep those two. They do not record
`force_reference_work` unless it was named, so they switch to auto = split. Inputs that name
`implicit_opac_update = false` or `implicit_one_pass = 8` (hipgate box.athinput, he_key,
tst he_slab_m1) keep those values.

A sweep started from t = 0 (tb/sp, tb/sl) is first order in both arms. The first step is
backward Euler (no stored slope), and its error dominates. So order tests must restart
from a file.

Not meaningful with wb_arad: the Lowrie-Edwards shock, the radiation-acoustic wave and a
Marshak wave (pgen rad_m1_beam). They have no well-balanced reference force.
`force_reference = wb_arad` needs a pgen that sets the reference.
