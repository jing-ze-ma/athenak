## 1. Which fluid arrays M1 addresses under MHD

- Conserved `pmhd->u0` has the same layout as hydro: IDN, IM1..IM3, IEN (+ scalars). IEN is
  the TOTAL energy: e_int + KE + |B|^2/2 (+ rho Phi with `<mhd>/etotgrav`).
- `u1` (U^n copy of the RK stage), `w0`, `wtemp`, `peos->eos_data` (same `EOS_Data`
  type), `use_etotgrav`, `phicc0`, `wbq0`, `use_wellbalance_dynamic`, `use_wb_x1`, `pcond`
  exist on MHD with the same names.
- B: face field `b0` (U^n copy `b1`), cell field `bcc0`. The C2P builds bcc0 from b0 by a
  plain face average (Cartesian) or the x1v-weighted average (spherical polar,
  general_mhd.cpp ConsToPrim). M1 must subtract EXACTLY that |bcc|^2/2 so its temperature
  equals the C2P's.

## 2. Mapping of the coupling terms

- Every M1 kernel that forms the gas internal energy does
  `eg = u(IEN) - KE - egrv`, egrv = rho Phi (etotgrav) or 0. Under MHD egrv becomes the
  NON-THERMAL, NON-KINETIC energy held in IEN: rho Phi + |B|^2/2. The write-back
  `u(IEN) = eg + KE + egrv + work` then restores |B|^2/2 unchanged. For hydro the added
  term is not formed (`if (mhd)` guarded), so the hydro arithmetic is bitwise identical.
- Energy exchange: changes e_int only (unchanged mapping). Radiation force: IM1..3 only
  (unchanged). Work: KE change (unchanged). Implicit velocity / vimp terms: v = m/rho from
  u0 (unchanged). Temperature, opacities (Opacity, opac update, VET start at U^n) use the
  same eg with |B|^2/2 removed; at U^n (u1) the field is the U^n field b1.
- B itself does not enter the radiation equations (grey M1, no Lorentz or plasma
  coupling): only the energy bookkeeping of IEN sees it.

## 3. Accessor (one code path)

`struct M1Fluid` (rad_m1.hpp), filled on the host each call from phydro or pmhd:
u0, u1, eos, etg, phicc, mhd flag, bcc (cell B of the current state = pmhd->bcc0; a dummy
for hydro). Kernels capture the struct members as locals (no class members in kernels).
U^n-state kernels (Time2VetStart) rebuild bcc from `b1` faces with the C2P's average.
Host paths that save/restore the gas (Time2Restore, MR u1<->u0, HydroConToPrim) also
copy / exchange / invert b for MHD (b0 <- b1 on restore; MHD's RestrictU/SendU/RecvU/
ApplyPhysicalBCs/Prolongate/ConToPrim; B is not touched by M1, so only u0 is exchanged).

## 4. WB force reference and `force_reference_work = split` under MHD

- The WB gravity source of the pgens acts on u0(IM1) and u0(IEN) only; the MHD x1 WB walk
  already exists (mhd_fluxes.cpp, BuildWBCache). What is hydro-only is the EFFECTIVE
  potential `phicc_wb / phi_wb_x1f` (EnableWBEffectivePotential, SetWBEffectivePotential)
  that `force_reference = wb_arad` requires: port it to MHD (aliases of phicc0/phi0.x1f
  unless enabled, so MHD default is bitwise), used by the MHD x1 WB reconstruction and
  BuildWBCache exactly as in hydro.
- `split`: the pgen WB source adds rho arad_ref v1 (stage velocity) to IEN; the solve's
  residual work and the radiation paying both are unchanged. Nothing B-specific.

## 5. Pgens

- Both pgens templated on the fluid class for their source / BC / history functions
  (`template <class F>`, dispatch on pmhd != nullptr); hydro instantiation = today's code.
- B initial condition: `problem/b0_1, b0_2, b0_3` uniform (box, force-free), and for the
  wedge a radial split monopole B_r = b0_r (r0/r)^2 (current-free); a weak field is set by
  `problem/beta_b` (plasma beta at the base). IEN += |B|^2/2. User x1 BCs copy b faces
  (zero gradient for the uniform field; r^-2 for the monopole).
- FATAL: MHD with any mode not ported (e.g. <mhd> + <hydro> without ion-neutral, sp with
  unsupported option), and a remaining `phydro`-only path reached with MHD.
