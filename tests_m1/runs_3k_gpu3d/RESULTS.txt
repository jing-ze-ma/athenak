--------------------------------------------------------------------------------
4.  WHY 2 GPUs GIVE 1.1x AND THE SMALL BOX RUNS AT 0.72e6: SIZE-INDEPENDENT COST
--------------------------------------------------------------------------------
Time per inner BiCGStab iteration, which is what dominates a step:
    S  (227k cells/GPU)   334.1/102.2 = 3.27 ms
    P1 (908k cells/GPU)   453.8/118.7 = 3.82 ms
    P2 (454k cells/GPU)   427.2/118.7 = 3.60 ms
A fit t = a + b N to S and P1 gives a = 3.09 ms, b = 0.81 ms per Mcell.
So on the production box 81 % of each inner iteration does NOT depend on the
cell count.  P2 predicted from the fit: 3.46 ms, measured 3.60; the extra
0.14 ms/its is the real MPI (4 Allreduce + 2 halo exchanges per iteration).
The step is latency-bound, for two measured reasons:
  (i) ImplicitTridiagSolve runs one thread per x1 column, and each thread does
      a serial 84-cell Thomas recurrence: 10816 threads for the whole box,
      2704 per MeshBlock.  MI300A needs ~10^5 resident threads.  Neighbouring
      threads are 84+2ng doubles apart in memory (LayoutRight, i fastest), so
      loads are not coalesced.  Measured: 908k cells in 719 us = 1.26 Gcell/s.
      Its time is set by the column length, not the column count, so it does
      not shrink when the columns are split over 2 GPUs.  (Inferred: S was not
      profiled.)
  (ii) 3432 launches and 489 host-blocking global reductions per step (4.06 per
      inner its: each Kokkos::parallel_reduce into a host scalar plus an
      MPI_Allreduce).  The median gap is 39 us, and the idle time is 124
      ms/cycle, ~36 us per launch.  This cost is identical per GPU whatever
      the box size, and on 2 GPUs every reduction also waits on the other rank.
The same applies to ImplicitHaloCopy: runs_3h_halo made it loop over rows
(m,n,k,j) with i serial inside, which removes an idiv per cell on the CPU.  On
the GPU that means ~13k threads per component with strided accesses: 108 us
per call for a shell copy.

--------------------------------------------------------------------------------
5.  HOST / DEVICE STATUS OF THE IMPLICIT-SOLVE KERNELS
--------------------------------------------------------------------------------
Every par_for and parallel_reduce in rad_m1_implicit.cpp is launched on
DevExeSpace (source), and the trace shows each exercised function as a HIP
kernel:
  ImplicitSolve, ImplicitTransverseTerms, ImplicitTridiagSolve,
  ImplicitOffDiagOp, ImplicitApplyOp, ImplicitPrecond, ImplicitBiCGStab,
  ImplicitHaloCopy, Opacity, ApplyClosureLimits, NewTimeStep, RSLACheck.
NO host fallback of any compute kernel.  Host-side parts:
  * every reduction result goes to host (the syncs in sect. 4);
  * the MPI_Allreduce of those scalars;
  * ImplicitGatherSolve / partition staging (h_view, host buffers): host-staged,
    but NOT exercised here (implicit_partition = none);
  * ImplicitTransTheta returns early (trans_limit = none);
  * ImplicitX1Halo and ImplicitAccel*: not called in this configuration.
The EOS evaluation (gas Newton, EOS cache) runs inside the ImplicitSolve
kernels on the device.

--------------------------------------------------------------------------------
6.  RANKED SPEED-UPS  (gain on P1's 454 ms/cycle; each tied to a number above)
--------------------------------------------------------------------------------
 1. PARALLEL LINE SOLVE in the preconditioner (ImplicitTridiagSolve).
    Measured: 173 ms/cycle = 35 % of wall, 47 % of kernel time, 1.26 Gcell/s,
    size-independent (sect. 4 i).  Options: PCR / cyclic reduction with one
    team per column in scratch memory (the two-stream already has one:
    rt_impl_solver = pcr, two_stream_column_partition.hpp), or a transposed,
    coalesced Thomas.
    Gain: kernel ~10x faster -> ~-155 ms/cycle -> ~1.5x overall.  It also
    removes the largest size-independent term, so small boxes and multi-GPU
    improve most.
    Effort: medium (1-3 days, port the PCR).  Risk: low; it only changes the
    preconditioner, so the converged solution is untouched to tolerance.  Not
    bitwise.
 2. INEXACT INNER SOLVES (input switch first, no code).  120 inner its per step
    solved to 1e-12 mean residual (tol 1e-10) at every one of 4.8 Picard passes.
    Early passes do not need 1e-10.  Try implicit_lin_tol 1e-6..1e-8, or a
    forcing term tied to the Picard residual.
    Gain: if inner its fall 30-50 %, the Krylov share (69 %) falls with them
    -> 1.2-1.5x.  Effort: minutes for the input test (one apudev job), a day
    for a forcing term.  Risk: medium; Picard pass count and NON-CONVERGED may
    rise, so gate on the hst fluxes.
 3. FEWER HOST SYNCS IN BiCGStab.  489 blocking reductions + 3432 launches
    per step; 25 % idle (124 ms/cycle); BiCGStab's own kernels 39 ms/cycle.
    Fuse the per-iteration dot products into one multi-value reduction (at
    most 2 syncs per its), keep scalars on the device where possible, fuse the
    vector updates; optionally pipelined BiCGStab (1 sync per its).
    Gain: ~-60..-90 ms/cycle -> 1.15-1.25x; more on 2+ GPUs, where each sync is
    also an Allreduce.  Effort: medium.  Risk: low for fusion, medium for
    pipelined BiCGStab (weaker stability; 29 breakdowns already in P1).
 4. GPU LAYOUT FOR ImplicitHaloCopy, or pack straight from iw.  56 ms/cycle =
    11-12 %, 108 us/call; the CPU-tuned row loop (sect. 4) is uncoalesced on
    the GPU.  Flatten over (m,k,j,i) of the shell under the device build, or
    skip the scratch copy and let the bvals pack/unpack read and write iw.
    Gain: ~-45..-50 ms -> ~1.1x.  Effort: low (hours).  Risk: low; the values
    are identical, gate with cmp as in runs_3h_halo.
 5. ImplicitOffDiagOp: 40.6 ms/cycle (8 %), 160 us per call = 5.7 Gcell/s for
    a 7-point operator.  Fuse it with ApplyOp and cut its array reads.
    Gain ~1.05x.  Effort: low-medium.  Risk: low.
 6. MULTI-GPU: do not scale out before 1-4.  Today 2 GPUs give 1.06x per step
    (453.8 -> 427.2 ms) because 81 % of an inner its is size-independent.
    After 1-4, weak scaling (>= 0.9 Mcell per GPU) is the efficient regime.
 7. EOS / gas Newton: <= 1.1 % of the step on GPU.  No work warranted;
    removing it entirely would save at most 1 %.

Combined 1+3+4 (independent kernels): 454 -> ~200 ms/cycle, ~2.3x, i.e.
~4.5e6 zone-cycles/s, which is within ~2.3x of the two-stream stack.  With a
successful 2 on top, parity with the two-stream stack per unit of simulated
time is plausible.  These are estimates from the measured shares, not
measurements.
