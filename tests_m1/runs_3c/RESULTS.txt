THE FORM.  F_f = (1 - w_f) F_central + w_f F_berthon with w_f in [0,1] from LAGGED face
quantities, stored per FACE in ifw(M1_IFW_AL / HCL / HCR / DG), so both cells that
share a face assemble from the same number and conservation is exact.
  W1 (tau)   w = exp(-(tau_face/tau0)^2)                      the user's suggestion
  W2 (f)     w = smoothstep((f_face - f_lo)/(f_hi - f_lo)),  f_face = max|f| of the two
  W3 (tau_f) W1*W2
w_f = 1 with mode = flux is BITWISE `berthon`, w_f = 0 is BITWISE `central` (the code
multiplies by exactly 1.0 or 0.0), which is what every "= central" / "= berthon" entry
below means literally.

M-MATRIX AND POSITIVITY.  The 3a2 argument is by COLUMNS.  A face contributes +nu c_L
to the diagonal of its left cell and -nu c_L to the lower off-diagonal of its right cell
(and +nu c_R / -nu c_R the other way), so each contribution has ZERO column sum and
non-positive off-diagonals; the central (face-eliminated) contribution has the same
structure with c_L = th c^2 dt w_i/dx.  A CONVEX combination with the SAME w_f in both
cells therefore again has zero column sum and non-positive off-diagonals, and the column
sums of the whole matrix stay 1 + SRCB >= 1: nonsingular M-matrix, E' > 0 at any dt.
The `dissipation` mode adds +w dk / -w dk pairs, which is the same structure, so it too
keeps the property.  The F0^n MEMORY term of the central form rides on the same weight
(the row uses om = 1 - w and the face update uses fn = (1-w) fn + (c/chat) gh), so the
stored face flux is always the flux the row applied.  NUMERICAL CHECK: minimum E over
the final dump, floor 1e-15, negatives counted:
  free-streaming pulse, W3/plm_dc, CFL 0.4 / 10 / 100:  5.59e-6 / 2.53e-2 / 1.34e-1, 0
  atmosphere, W3, CFL 1 / 100 / 1e4:                    2.000000e+00, 0
The floor was never active on a blend solution in any gate.

VERDICT
=====================================================================================
RECOMMENDED: implicit_flux = blend, implicit_blend = tau_f (W3), implicit_recon = dc for
production columns and plm_dc where a front must propagate.  It is bitwise `central` on
every diffuse problem measured (G1, G3, G4, G5, G6, G7, G8) and bitwise `berthon` in
free streaming (G2), so it costs nothing and buys 1.5x (dc) to 2.5x (plm_dc) on G2.
THE DEFAULT IS NOT CHANGED: the decision rule for a new default was "at least as good as
central everywhere AND improves G2 AND G3", and G3 is NOT improved (0.0144 = central,
against berthon's 0.0104).  `implicit_flux = central` therefore stays the default.
implicit_blend_fmode = max is the right choice: `mean` halves the free-streaming gain
(0.498 against 0.922 at CFL 0.4, 0.351 against 0.786 at CFL 10) because at the EDGE of a
pulse one of the two cells is still diffuse and the mean pulls the weight down exactly
where the upwind part is needed; on the atmosphere the two are identical (1.353e-3).
The user's tau-only weight (W1) must NOT be used: it fails G1 (3.7e-1), degrades G4 by
157x and wrecks G8 (245x the residual force, Picard never converging).
implicit_blend_mode = dissipation is REJECTED: it does not help the front (0.324 at
CFL 0.4, below plain central's 0.369) and destroys the Picard convergence (17-28 passes
against 2).  implicit_recon_npass (freezing the plm limiter after N passes) is REJECTED:
npass = 3 makes G2 worse (0.444 against 0.922) and does not restore convergence -- the
limit cycle is driven by the re-lagged closure and wave speeds, not by the limiter.
